# .work — 项目工作区文档

本目录承载 Aluka IDE 的**需求、计划与每日执行跟踪**，是 AI 协作开发的事实来源（Single Source of Truth）。

## 目录结构

```
.work/
├── REQUIREMENTS.md       # 需求分析文档（FR/NFR/扩展兼容分级/风险）
├── DEVELOPMENT_PLAN.md   # 开发计划（MVP 定义、M0~M7 里程碑、排期、质量门）
├── README.md             # 本文件
└── TODO/                 # 每日执行跟踪
    ├── TEMPLATE.md       # 新建每日 TODO 的复制模板
    └── TODO_YYYYMMDD/    # 每日任务目录
        └── README.md     # 当日目标、任务清单、验收标准、验证记录
```

## 每日工作流

1. 复制 `TODO/TEMPLATE.md` 为 `TODO/TODO_<当日日期>/README.md`（日期格式 `YYYYMMDD`）。
2. 填写"今日目标"与任务清单（每条任务含**具体目标**与**可勾选的验收标准**）。
3. 开工：状态置 🔄；完成：勾选验收项并置 ✅；受阻：置 ⛔ 并写明原因与影响。
4. 收口：填写"验证记录"（执行的命令、结果、UI 截图路径），通过 §6 质量门后当日 TODO 才算闭环。

## 状态标记约定

| 标记 | 含义 |
| --- | --- |
| ⬜ | 未开始 |
| 🔄 | 进行中 |
| ✅ | 完成（验收标准全部勾选） |
| ⛔ | 受阻/放弃（必须附原因） |

## 文档维护规则

- 需求变化 → 改 `REQUIREMENTS.md` 并追加变更日志；
- 计划/里程碑变化 → 改 `DEVELOPMENT_PLAN.md` 并追加变更日志；
- 历史每日 TODO **只读归档**，不回改内容（仅允许补验证记录）。
